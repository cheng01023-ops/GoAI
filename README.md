# GoAI —— 用 C 语言从零写的围棋 AI（AlphaZero 风格 · 可自己训练 · 可对弈）

一个**不依赖任何深度学习框架**的围棋 AI：规则、蒙特卡洛树搜索（MCTS）、卷积神经网络的前向与反向传播
全部用 **C11** 手写。它可以在你自己的电脑上**自我对弈训练**，练强了直接跟人下棋。

- 🎯 **纯 C 实现**：不依赖 PyTorch/TensorFlow 也能训练（CPU 版）；有 NVIDIA 显卡时可选 PyTorch 加速
- 🧠 **AlphaZero 思路**：策略+价值双头 CNN、PUCT 搜索、Dirichlet 噪声探索、镜像数据增强、胜率晋级机制
- 🖥️ **三种用法**：终端全屏对弈（macOS/Linux）、纯文本对弈（Windows 零依赖）、GTP 协议（接 Sabaki 等图形界面）
- 📦 **开箱即玩**：`standalone/` 里的 `GoBoard.exe` 已把训练好的权重编译进程序，双击就能下
- ⚡ **榨干硬件**：多线程自对弈 + 可选 GPU 批量推理服务（C 引擎搜索 + Python/PyTorch 只做批量前向）

|---|---|---|---|

## 快速开始

### ① 只想下棋（最省事）

- **Windows**：解压 `standalone/`，双击 `PLAY_NOW.bat` —— 不用装编译器、不用装 Python
- **macOS / Linux**：`cd standalone && make goboard && ./build/GoBoard --sims 200`（全屏棋盘，方向键操作）

对弈程序默认用**编译进程序内部**的 v3 权重。想换网络：`--weights 你的.bin`。

### ② 自己训练（CPU，任何电脑都能跑）

**macOS / Linux**

```bash
make -s all && make -s test          # 编译 + 自检（226 项测试）
./build/GoAI train --size 9 --channels 32 --forever \
  --games 40 --sims 140 --steps 250 --threads 8 \
  --gate 1 --gategames 20 --eval-every 3 --out runs_live
```

**Windows**（需要 MSYS2 或 [w64devkit](https://github.com/skeeto/w64devkit/releases)）

```bat
mingw32-make -f Makefile.win all
build\GoAI.exe train --size 9 --channels 32 --forever --games 40 --sims 140 --steps 250 --threads 8 --out runs_live
```

- 训练会**一直跑**，每轮把最新权重写到 `runs_live/latest.bin`；`--gate 1` 打开晋级赛，
  只有明显更强的版本才会覆盖 `best.bin`
- 想看进度：`runs_live/status.txt`（每 2 秒刷新）、`runs_live/train_log.csv`（每轮一行）、
  `python3 tools/plot.py runs_live/train_log.csv`（画曲线）
- 停止：在输出目录建一个名为 `STOP` 的空文件即可（会在当前轮结束后保存权重退出）
- 随时对弈：`./build/GoAI eval --a 网络.bin --b random --games 40 --sims 100` 看胜率

### ③ 有 NVIDIA 显卡：榨干 GPU

CPU 版里搜索是并行瓶颈；想让显卡真正满载，用**推理服务**架构：

```bash
# 服务端（可跑在 5080 上）：批量推理 + GPU 训练 + 权重热更新
pip install -r gpu/requirements.txt
python gpu/server.py --size 19 --channels 256 --device cuda --amp bf16 --max-batch 2048 --out runs_gpu

# 对弈端（C 引擎跑搜索，几千盘并行）
./build/GoAI gtrain --remote 127.0.0.1:8899 --threads 16 --slots 64 --sims 64 --size 19
```

实测（CPU 服务端做下限参考）：服务端评估 **30,939 局面/秒**、推理忙碌 **94%**，
而早期"纯 Python 搜索"方案显卡只用到 8% 左右。

## 训练进阶：让曲线继续往下走

9 路 32 通道练到 3 万多局后会遇到平台期：策略损失在 2.7~2.9 之间来回震荡、晋级赛长期 50%。
原因是**学习信号饱和 + 固定学习率**，不是训练时间不够。程序内置了四个机制来突破它：

### 1. 学习率衰减（必开）

    --lr 0.005 --lr-decay-every 100 --lr-decay-factor 0.85 --lr-min 0.0005

第 k 轮的学习率 = `lr * factor^(k / every)`，夹在 [lr_min, lr] 之间。
按**绝对轮次**计算，所以中途停止再 `--resume` 不会打乱计划。
每轮的学习率会打印在控制台，并写进 `train_log.csv` 的 `lr` 列。

### 2. 固定锚点评估（判断"到底有没有变强"）

    --anchor versions/goai9x9_v3_33kgames.bin --anchor-every 10 --anchor-games 20

拿一个**永不再变**的网络当尺子，每隔 N 轮和它对战若干局，把胜率写进 CSV 的
`anchor_winrate` 列。因为它不随训练漂移，这条曲线比"对上一版胜率"干净得多 ——
**这是判断训练是否真的在进步的主指标**。

### 3. 退化回滚保护

    --rollback 1 --rollback-patience 3

连续 N 次晋级赛胜率低于 45%（判定练歪了），自动载入 `best.bin` 重新出发，
并把 Adam 的一阶/二阶动量清零，避免带着"坏记忆"继续跑。

### 4. 评估带置信区间

晋级赛和锚点评估都会打印 `±X%` 的 95% 置信区间（`1.96*sqrt(p(1-p)/n)`）。
**看进步时务必对照它**：12 局打出的 58% 和 42% 在统计上没有区别。

### 推荐配置

    ./build/GoAI train --size 9 --channels 32 --forever \
      --resume runs_v4/latest.bin \
      --games 40 --sims 140 --steps 250 --batch 64 \
      --lr 0.005 --lr-decay-every 100 --lr-decay-factor 0.85 --lr-min 0.0005 \
      --threads 10 --evalgames 12 --evalsims 20 \
      --gate 1 --gategames 40 --eval-every 5 \
      --anchor versions/goai9x9_v3_33kgames.bin --anchor-every 10 --anchor-games 20 \
      --rollback 1 --rollback-patience 3 --out runs_v4

### 训练效率测量（13 路 32 通道，160 模拟，10 线程）

每轮 40 局 195 秒的耗时分布：

| 阶段 | 耗时 | 占比 |
|---|---|---|
| 自对弈 | 162.6s | **84%** |
| 梯度训练 | 11.3s | 6% |
| 评估/晋级/锚点 | 19.6s | 10% |

结论：
- **瓶颈在自对弈**，不在训练（250 步梯度只占 6%）—— 所以"并行化反向传播"这类优化收益极小
- 自对弈的并行度：单线程 25.8 秒/局 → 10 线程 4.07 秒/局，**加速 6.4 倍**
  （M5 是 4 性能核 + 6 能效核，等效约 6 核，已接近硬件上限）
- 想再快只能让**每次模拟更便宜**（编译优化 / SIMD / 树复用），而不是加线程

### train_log.csv 的列

`iteration, games, positions, policy_loss, value_loss, param_norm, winrate_vs_random,`
`gate_winrate, elapsed_s, lr, anchor_winrate, selfplay_s, train_s, eval_s`

（`gate_winrate` = 对"当前最佳"的胜率，`-1` 表示这一轮没打；`anchor_winrate` 同理）

## 换大棋盘：用热启动省掉前期学习

9 路练得差不多了想上 13 路 / 19 路，不必从随机权重开始。
**卷积层学到的棋形知识（气、连接、断点、边角手段）与棋盘大小无关**，
只有策略头/价值头依赖棋盘点数。`tools/warm_start.py` 负责把前者搬过去：

    # 9 路 32 通道 -> 13 路 64 通道（通道数不同时用切片迁移）
    python3 tools/warm_start.py --from versions/goai9x9_v3_33kgames.bin \
        --size 13 --channels 64 --vhidden 64 --out warm13.bin

    # 自检（校验逐值复制是否正确）
    python3 tools/warm_start.py --selftest

输出会明确告诉你哪些层被完整迁移、哪些做了切片迁移、哪些必须重学：

    完整迁移: pb, vb
    切片迁移: c1w(1152/2304), c1b(32/64), c2w(9216/36864), c2b(32/64), pw(64/128), vw(32/64)
    重新学习: pfcw, pfcb, vfc1w, vfc1b, vfc2w, vfc2b

拿到 `warm13.bin` 就能直接开始训练：

    ./build/GoAI train --size 13 --channels 64 --forever \
      --resume warm13.bin --games 40 --sims 200 --steps 250 \
      --lr 0.004 --lr-decay-every 100 --lr-decay-factor 0.85 \
      --threads 10 --gate 1 --gategames 40 --eval-every 5 \
      --anchor warm13.bin --anchor-every 10 --anchor-games 20 --out runs13

> **实测开销（M5，10 线程）**：13 路每局约 180 手（9 路约 110 手），局面数 2.1 倍，
> 搜索树也更大 —— 每轮 40 局约 4.4 分钟，是 9 路（36 秒）的 **约 8 倍**。
> 也就是说 13 路一夜大约能跑 130 轮 / 5,000 局。用 --sims 控制强度，13 路建议 160~300。
> 用 `--sims` 控制强度：13 路建议 200~400。

## 性能优化记录

### 卷积前向重写（1.8× ~ 3.0× 提速）

单线程前向微基准（交替测量取稳定值）：

| 规模 | 优化前 | 优化后 | 加速 |
|---|---|---|---|
| 9 路 32 通道 | 0.272 ms | **0.191 ms** | 1.4× |
| 13 路 32 通道 | 0.593 ms | **0.322 ms** | 1.8× |
| 19 路 64 通道 | 6.221 ms | **2.076 ms** | **3.0×** |

**做法**：原来的实现是"逐像素 + 每个像素跳 9 次边界判断"；改成
按 (输出通道, 输入通道) 配对**累加整张输出平面**：

- 内部像素（13 路时占 72%）走**无分支快路径**，边界像素单独处理
- 累加平面只有 n² 个 float（13 路 = 676 字节），常驻 L1
- 内层循环对连续 x 访问，**可被编译器自动向量化**
- 卷积核的 9 个权重先读进局部常量，避免重复寻址

**正确性**：与旧实现输出**逐字节一致**（13 路与 9 路网络分别对拍），
91 项测试全部通过（含有限差分梯度校验）。

**生产环境实测**（13 路 32 通道，每轮 40 局，同一配置前后对照）：

| 阶段 | 优化前 | 优化后 | 加速 |
|---|---|---|---|
| 自对弈 | 162.6s | **88.3s** | **1.84×** |
| 梯度训练 | 11.3s | 6.0s | 1.9× |
| 评估 | 19.6s | 8.3s | 2.4× |
| **整轮合计** | **193.5s** | **102.6s** | **1.89×** |

### 三轮优化累计效果（13 路 32 通道，每轮 40 局，10 线程）

| 优化阶段 | 自对弈 | 加速 | 做法 |
|---|---|---|---|
| 最初（朴素卷积） | 162.6s | 1.00× | 逐像素 + 每像素 9 次边界判断 |
| 第一轮 | 88.3s | 1.84× | 按输出通道累加 + 内部区域无分支 |
| 第二轮 | 44.1s | 3.69× | 3×3 卷积拆成 9 个 tap，每个 tap 整行 axpy |
| 第三轮 | **34.2s** | **4.75×** | 手写 NEON intrinsics（4 宽 FMA） |

整轮耗时 193.5s → **40.5s（4.8×）**，梯度训练 11.3s → 3.0s。
三轮优化后输出与最初**数值完全一致**（最大绝对差 0），91 项测试全程通过。

### 单次模拟的成本构成（优化后）

| 部分 | 耗时 | 占比 |
|---|---|---|
| 网络前向 | 0.156 ms | ~55% |
| 树操作 + 特征编码 + 回传 | ~0.13 ms | ~45% |

下一步优化方向：进一步压网络前向（行宽补到 4 的倍数）、
树复用（同样的模拟次数换更深搜索）。

### 训练耗时分布（13 路 32 通道，10 线程）

| 阶段 | 占比 |
|---|---|
| 自对弈 | **84~90%** |
| 梯度训练（250 步） | 6~13% |
| 评估 + 晋级 + 锚点 | 2~10% |

推论：优化重点应该放在**每次模拟的成本**上（网络前向 + 树操作），
而不是并行化梯度训练 —— 后者最多只能拿回 13%。

### 编译选项实测

`-march=native` 在这台 M5 上**没有稳定收益**（A/B 交替测量落在噪声内）。
Makefile 仍保留 `NATIVE=1` 开关，但默认关闭以保证二进制可跨机器分发。

### A/B 实验：树复用（Reuse）反而有害

树复用是指走完一手后保留那棵子树，下次搜索接着用（Leela Zero 等实现常用）。
理论上同样模拟次数能搜得更深。实测（9 路，从 v4 出发各跑 20 轮，锚点都是 v4）：

| 组 | 第 10 轮锚点 | 第 20 轮锚点 | 策略损失 | 价值损失 |
|---|---|---|---|---|
| 复用关 | 30% | **40%** | 2.671 → 2.707 ↑ | 0.645 → 0.730 ↑ |
| 复用开 | 10% | **15%** | 2.588 → **2.207** ↓ | 0.852 → **0.612** ↓ |

**训练损失明显更好，但实际棋力明显更差。**

原因：复用得越深，搜索给出的策略目标越"尖锐"（集中在一两条最佳线），
网络学会的是**狭窄的确定性走法**而不是"多个好点的分布"，导致

- 策略塌缩：网络对自己的首选着法过度自信，低模拟次数下反而下得差
- 自对弈对局趋同：总是沿同一条线走，训练数据多样性下降

**结论：在本项目的配置（140~160 次模拟 + 小网络）下默认关闭树复用。**
代码与 `--reuse 1` 开关保留，等将来模拟次数大幅提高（如 800+）时可以再验证。

> 一个更普遍的教训：**训练损失不是棋力**。这轮 A/B 里，损失降得最多的那一组
> 棋力反而最差 —— 如果只看损失，会得出完全错误的结论。只有固定锚点对局才看得清。

## 核心结论汇总（长期更新）

> 这一节把所有实验的结论压缩成一张表，方便快速了解"什么有用、什么没用、为什么"。
> 每条结论都有对应的实测数据和 A/B 实验，详见后面的「优化日志」。

### ✅ 已采纳（有实测收益）

| 改动 | 收益 | 证据 |
|---|---|---|
| 卷积前向重写（累加+无分支 → 9-tap axpy → NEON） | **训练吞吐 4.75×** | 自对弈 162.6s → 34.2s（40 局 13 路） |
| 成对开局评估 | 评估噪声几乎归零 | A vs A 从 ±12.5 点波动变为**完全稳定 50%** |
| 固定锚点 + 置信区间 | 能区分"真进步"与"运气" | 所有后续实验的判据 |
| 学习率衰减 + 退化回滚 | 防止训练把棋力练坏 | 实测触发并正确恢复 best.bin |
| 每步模拟次数 320（原 160） | 同等算力下锚点 67% vs 40% | 13 路 A/B |
| 每轮对局数 200（原 40） | 同数据量下锚点好 10 个百分点 | 13 路 A/B |
| 卷积热启动迁移 | 13 路训练从 0 直接继承 9 路特征 | 逐值校验 |
| 残差块零初始化 | 保留全部转移棋力 | 对随机 91.7%（未做时仅 12%） |

### ❌ 已否决（实测无收益或有害）

| 改动 | 结论 | 证据 |
|---|---|---|
| 树复用（--reuse） | **有害** | 损失降得更多但锚点 15% vs 40%（策略塌缩） |
| 降低学习率 | 无效 | 0.001→40%、0.0003→20%、0.0001→38%（全 <50%） |
| `-march=native` | 无稳定收益 | A/B 落在噪声内 |
| 反向传播重写 | 无收益 | A/B 163.3s vs 166.1s（噪声内） |

### 🔑 最重要的三条规律

1. **训练损失不是棋力。** 树复用那组损失降得最多，棋力却最差。
   只有"固定锚点 + 成对开局"的对局数据能反映真实强弱。

2. **已收敛的网络继续训练会退化。** 三次独立复现（锚点 40% / 28% / 42%），
   且与学习率无关、加宽数据只能缓解。根因推断是网络表达力不足（原来仅 2 层卷积）。

3. **结构正确 ≠ 训练能 work。** 残差块的梯度校验精确到 0 偏差、106 项测试全过，
   但少了"零初始化"这个细节，真实训练直接发散 —— 单元测试发现不了，
   必须看行为指标（对随机胜率、每局手数）。

### 📐 复现实验的规范（踩坑总结）

- 评估必须用**成对开局**（同一开局双方各执黑一次），否则 20~40 局的波动高达 ±15%
- A/B 必须**独占机器**并**交替测量**；跨时间的墙钟对比会被温度/负载完全污染
  （曾出现同一版本差 66% 的"测量"）
- 换源码后构建要用 `rm -f build/net.o` 强制重编，并用 md5 校验两个二进制**确实不同**
  —— 否则会拿同一个程序跑两次"A/B"
- macOS 没有 `timeout` 命令（用了会静默失败）
- 长任务必须 `nohup` 分离，否则工具调用超时会连进程组一起杀掉

| 8 | 卷积前向重写（累加+无分支） | ✅ 采用 | 生产 162.6s→88.3s（1.84×），输出逐字节一致 |
| 9 | 9-tap axpy 卷积 | ✅ 采用 | 88.3s→44.1s（累计 3.69×） |
| 10 | NEON 手写向量化 | ✅ 采用 | 44.1s→34.2s（累计 4.75×） |
| 11 | 树复用（--reuse） | ❌ **有害，默认关闭** | A/B：损失降更多但锚点 15% vs 40% |
| 12 | 模拟次数 160 vs 320 | 采用 320 | 同等时间：锚点 67% vs 40% |
| 13 | 成对开局评估 | 采用（默认开启） | A vs A 从波动 ±12.5 点变为完全稳定 50% |
| 14 | 每轮梯度步数 250 | 抑制（数据太窄） | 从已收敛网络微调 6 轮后锚点仅 28% |
| 15 | 学习率扫描 | 排除（与 LR 无关） | 0.001→40%, 0.0003→20%, 0.0001→38% |
| 16 | 每轮对局数 200 | 采用 | 同数据量下比 40 局/轮好 10 个百分点 |
| 17 | 残差块 --blocks | 进行中 | 梯度校验 0 偏差；2 块 = 6.4 倍前向开销 |
| 18 | 第 ⑤ 步：领地头 + 值分布 | 进行中（见「第 ⑤ 步」一节） | 梯度校验 2e-05；**顺带修掉残差块下头部 1x1 梯度错误**（偏差 0.15 → 1.8e-04）|
| 19 | 值头热启动标定（标量→分布） | ✅ 采用 | 未标定锚点 2.5%，标定后起点 45%（60 局成对开局）|

### 第 12 项实验细节：搜索深度（模拟次数）

13 路，从同一检查点出发，锚点都是起点权重：

| 对比口径 | 160 次模拟 | 320 次模拟 |
|---|---|---|
| 同等对局数（240 局） | 锚点 57%，策略损失 4.20 | 锚点 67%，策略损失 3.93 |
| 每轮耗时 | 43s | 91s |
| 同等时间（约 8.6 分钟） | 12 轮 480 局 -> 锚点 40% | 6 轮 240 局 -> 锚点 67% |

结论：固定算力预算下搜索更深更划算 —— 每局棋的学习价值更高；
而且更好的搜索目标同时缓解了策略塌缩（损失降、棋力也降）的现象。
主训练已切换为 --sims 320。

### 一条贯穿始终的教训

**训练损失不是棋力。** 第 11 项（树复用）里，损失降得最多的一组棋力反而最差。
只有"固定锚点 + 置信区间"的对局数据能反映真实强弱 —— 这也是本项目坚持
每项改动都做 A/B 的原因。

### 评估方法升级：成对开局（Paired Openings）

**问题**：原来每局都从空盘开始、前 4 手带温度随机 → 每局开局不同 →
20~40 局的胜率波动高达 ±15%，A/B 实验需要很大的真实差异才能被测出来。

**做法**：每对局先用**固定种子**生成同一个随机开局（默认 4 手），
再让双方在**同一开局**下各执黑一次。开局种子固定 → 不同实验、不同时间可比。

**效果**（同一个网络自己对自己，真实胜率应为 50%）：

| 模式 | 5 次重复 | 说明 |
|---|---|---|
| 不成对开局 | 62.5% / 60.0% / 52.5% / 62.5% / 50.0% | 波动 ±12.5 点，均值还偏 7.5 点 |
| **成对开局** | 50.0% / 50.0% / 50.0% / 50.0% | **完全稳定** |

**性质**：
- 同一批开局内**完全确定性**（v4 vs v3 两次不同随机种子都是 66.2%）
- 换一批开局仍有约 ±5~9 点不确定性（20 对开局）→ 加对局数或换种子检查鲁棒性

**用法**：

    # 默认就开启成对开局（4 手）
    ./build/GoAI eval --a 新.bin --b 旧.bin --games 40 --sims 100

    # 换一批开局做鲁棒性检查
    ./build/GoAI eval --a 新.bin --b 旧.bin --games 40 --sims 100 --open-seed 7

    # 关掉（回到旧方法做对照）
    ./build/GoAI eval --a 新.bin --b 旧.bin --games 40 --sims 100 --open-plies 0

> 意义：从这一版起，晋级赛与锚点评估都是**低噪声**信号，
> "真进步"和"运气好"可以分开 —— 这是后续所有训练改进能被可靠验证的前提。

### 观察：切换到深搜索后价值损失升高（正常现象）

13 路训练中，从 160 次模拟切到 320 次模拟后，价值损失从 0.41 跳到 0.55~0.76。
逐轮数据说明这不是退化：

| 阶段 | 每局手数 | 价值损失 |
|---|---|---|
| 160 模拟（第 1~13 轮） | 238 → 143（网络学会收束，不再乱填） | 0.73 → 0.41 |
| 320 模拟（第 14~19 轮） | 193~211（对手抵抗更强、棋局更胶着） | 0.55~0.76 |

**原因**：搜索更深 → 双方下得更强、更少提前停着 → 棋局变长且胜负接近 →
中盘局面的最终胜负更难预测 → 价值损失天然升高。

**推论**：价值损失的绝对值不能跨配置比较，只能在同一配置内看趋势；
跨配置比较必须靠成对开局的锚点胜率。

### 关键规律：已收敛的网络继续训练会退化（第三次复现）

| 实验 | 起点 | 训练量 | 结果 |
|---|---|---|---|
| 9 路 v4 + 微调 | v4 (对 v3 66.2%) | 20 轮 × 40 局 | 锚点 **40%** ✗ |
| 9 路 v4 + 树复用 | v4 | 20 轮 × 40 局 | 锚点 **15%** ✗ |
| 13 路 best + 微调 | 13 路 best | 6 轮 × 40 局 @320 模拟 | 锚点 **28~30%** ✗ |

三次都出现同一现象：**训练损失（有时下降有时上升），但锚点胜率显著低于 50%**
—— 也就是"继续训练只会让它变差"。

**根因假设**：每轮只有 40 局（约 8,000 个局面），而每轮做 250 步 × 64 批量
= 16,000 个样本 ≈ 对同一批高度相关的数据过 2 遍。自对弈数据本身相关性很强
（同一网络、同一条主线），于是网络**过拟合最近这批数据**，策略变得过度自信、
失去多样性 —— 下棋时反而更弱。

**应对方向**（下一步实验）：
1. **每轮对局数 40 → 200**：让每次梯度更新看到更宽的数据分布
2. **每轮梯度步数 250 → 100**：减少对同一批数据的重复咀嚼
3. 两者结合：大局数 + 适度步数

> 这也解释了为什么"训练损失"和"棋力"经常背离 —— 损失是在**当前这批数据**上算的，
> 过拟合会让它变好看，但棋力下降。

### 实验：每轮对局数 40 vs 200（验证"数据太窄"假设）

同样 400 局训练量、同一权重起点、同一锚点、成对开局评估：

| 每轮局数 | 200 局时锚点 | 400 局时锚点 | 结论 |
|---|---|---|---|
| 40（现行） | 32% | **42%** | 明显退化 ✗ |
| **200** | **42%** | （进行中） | 同样 200 局时**好 10 个百分点** ✓ |

**部分支持假设**：加大每轮对局数确实能减缓退化（同数据量下 42% vs 32%），
但**仍未阻止退化**（仍低于 50%）。

**综合三次退化实验的结论**：
在"32 通道小网络 + 自对弈 + 固定学习率"这套配置下，13 路网络已经收敛；
继续训练只会让棋力下降。**数据管线只是部分原因，网络容量不足是更根本的限制。**

**下一步**：换更大容量的网络（13 路 64 通道 ≈ 4 倍容量）。
本轮的性能优化（卷积快 4.75 倍）正好让这个大网络变得可负担 —— 这是下一步的主实验。

### 实验：学习率扫描（检验"LR 太高导致退化"）

从 13 路 best.bin 出发，各训练 200 局（1 轮），成对开局评估 40 局：

| 学习率 | 锚点 |
|---|---|
| 0.001 | 40% |
| 0.0003 | **20%** |
| 0.0001 | 38% |

**结论：退化不是学习率造成的** —— 降低 3 倍反而更差。
（注意：每臂的自对弈数据是各自随机生成的，这个对比混入了数据随机性；
但两臂都明显低于 50%，说明"从已收敛网络继续训练会退化"是稳健现象。）

### 新的根因假设：网络太浅

我们的网络结构是 **2 个卷积层**（4→32→32）加上策略/价值头 —— 没有任何残差块。
而 AlphaZero 用的是 20~40 个残差块。

一个 2 层网络**表达力不足以吸收搜索给出的改进**：搜索能给出更好的着法分布，
但网络学不到能泛化的表示，于是只能过拟合到当前这批自对弈数据上 ——
表现为"训练损失好看、实战棋力下降"。

这与前面所有观察一致：
- 数据加宽（200 局/轮）能缓解但不能消除 ✓
- 降低学习率无效 ✓
- 树复用（目标更尖锐）让它更糟 ✓

**下一步方向**：给网络加**残差块**（`--blocks N`），用卷积深度换表达力。
本轮的性能优化（卷积前向快 4.75 倍）让加深度变得可负担。

## 网络容量：残差块（`--blocks N`）

### 为什么加

前几轮实验证明：**已收敛的网络继续训练只会退化**，而且这个现象
与学习率无关（0.001→40%、0.0003→20%、0.0001→38%）、加宽数据只能缓解。
最合理的解释是网络表达力不足 —— 我们原来只有 **2 个卷积层**（4→32→32），
而 AlphaZero 用 20~40 个残差块。2 层网络学不到能泛化的表示，
只能过拟合到当前这批自对弈数据上，于是"损失好看、棋力下降"。

### 实现

- `--blocks N` 在 conv2 之后插入 N 个残差块：`h <- relu(convB(relu(convA(h))) + h)`
- 前向/反向/缓存全部配套；**有限差分梯度校验最大偏差 0.00e+00（0/80 超差）**
- `.bin` 格式升级：新 magic `0x474F414A`（"GOAJ"）带 `blocks` 字段，
  **旧格式仍能读取**（当作 blocks=0）
- 测试从 99 项增加到 **106 项**
- 热启动迁移：`--blocks N --resume 旧网络.bin` 会把形状相同的权重
  （两层卷积 + 四个头部）原样搬进新结构，残差块随机初始化

### 前向开销实测（13 路 32 通道）

| 配置 | 前向耗时 | 相对 |
|---|---|---|
| blocks=0（原来） | 0.17 ms | 1.0× |
| blocks=1 | 0.60 ms | 3.5× |
| blocks=2 | **1.09 ms** | 6.4× |
| blocks=4 | 2.08 ms | 12× |

每块约 +0.23 ms（两个 C×C×9 卷积）。加上前面 4.75 倍的卷积优化，
"2 个残差块"在 CPU 上从完全跑不动变成可负担（每轮 100 局约 10 分钟）。

### 进行中的实验

`runs_blk/`：13 路 + 32 通道 + **2 个残差块**，从 13 路 best.bin 热启动，
100 局/轮，160 次模拟，成对开局评估。
**判据：锚点胜率能否突破 50% 并持续上升** —— 这是"容量假设"的直接检验。

### 失败与修复：残差块必须零初始化

**第一次残差块实验（runs_blk）发散了：**

| 指标 | 结果 |
|---|---|
| 第 10 轮锚点（对固定基准，30 局） | **0.0%**（全败）✗ |
| 对随机胜率 | 从 90% 掉到 12~38%，一直没恢复 ✗ |
| 损失 | 3.40 后反弹到 4.00（发散）✗ |

**根因**：残差块随机初始化后直接接在预训练特征之后，
随机残差把转移过来的特征破坏了 —— 而残差路径还会放大误差，训练随之发散。

**修复**：每个残差块的**第二个卷积（含偏置）零初始化**，
使块初始就是**恒等映射**（ResNet / AlphaZero 的标准做法）：

    h_out = relu(convB(relu(convA(h))) + h)   当 convB 权重为 0 时 => h_out = h

这样热启动后网络行为与原网络**完全一致**，训练只能在保持棋力的基础上做加法。

**顺带修好的测试问题**：零初始化会让残差块前半部分的梯度恒为 0，
有限差分退化成噪声（曾报 3/80 超差）。现在梯度测试会先把块权重随机化再校验，
结果回到**最大绝对偏差 0.00e+00**。

**第二轮实验（runs_blk2）**已用零初始化重启，并在第 1 轮检查对随机胜率是否回到 ~90%
—— 这直接验证"零初始化保住了预训练棋力"。

### 零初始化修复的验证结果（决定性）

| 指标 | 无零初始化 ✗ | 零初始化 ✓ |
|---|---|---|
| 对随机胜率 | 12% | **91.7%** |
| 每局手数 | 35 手（早早停着结束） | **195.6 手** |
| 第 1 轮策略损失 | 4.70（之后反弹到 4.00） | **3.466**（继续下降） |
| 每轮耗时 | 98s（对局太短） | 480s（真实对局） |

**结论：零初始化完全解决了问题** —— 转移的棋力一点没丢（91.7% 正是转移前 13 路 best 的水平），
残差块从"恒等映射"出发，训练可以只在保持棋力的前提上做加法。

> 这也是一个典型教训：**结构上正确的实现（梯度校验 0 偏差）不代表训练能work**。
> 残差块少了零初始化这个"仪式性"细节，整个实验就发散了 —— 而它单靠单元测试是发现不了的，
> 必须看真实训练的行为指标（对随机胜率、每局手数）。

## 第 ⑤ 步：辅助目标（领地头 + 值分布）

> 目的：提高**学习信号密度**。原来每个局面只产出 1 个胜负值（1 个标量），
> 而 9 路一盘棋有 81 个点位的归属信息被丢掉了。这两项是 KataGo 相对 AlphaZero
> 提升最大的两个改动。

### 领地（ownership）辅助头

- 在最后一个特征图后加一个 1x1 卷积头 `C -> 1`（n*n 个 logits），参数 `ow(C) + ob(1)`
- 标签来自终局棋盘（`board_ownership`）：棋子归自己的颜色；空区只接触一种颜色就归它，
  同时接触两色算中立。黑方视角编码 `{+1, 0 中立, -1}`，训练时按该局面的行棋方
  翻成 `{1, 0.5, 0}`（与值头同一视角）
- **存储**：一盘棋只存一份 81 字节 int8 的归属表，样本里只记"棋局号"，采样时按号取。
  槽位被后面的棋局覆盖时该样本自动跳过领地损失（不会读到错的地盘），运行结束会打印数量
- **损失**：`total = policy_ce + value + OWN_WEIGHT * own_bce`，
  反传 `d_logit = (sigmoid(z) - target)/nn`，梯度累加到 `d_h2`（与策略/价值头相加）
- 数据增强（8 种对称）会把归属图和棋盘、策略一起做同一个变换
- 权重用 `--own-weight 0.15`（KataGo 同量级）；A/B 扫 0 / 0.15 / 0.3

### 值目标分布化

- 值头第二层从 `H -> 1` 改成 `H -> K`（K = 33 个桶，均匀覆盖 [-1, +1]），
  损失从 MSE 改成**交叉熵**（one-hot 到 z 落入的桶，梯度 `p_k - t_k`）
- 搜索仍然只要一个标量：分布的期望 `sum p_k * bucket_center_k`
- ⚠️ **交叉熵与 MSE 不可比**：CSV 里 `value_loss` 换了含义（初始约 `log 33 = 3.50`），
  判断有没有变强只看**成对开局锚点**，不要跟历史 MSE 数字比

### 格式兼容（不加第三个 magic）

`GOAJ` 头部第 5 个字段从 `blocks` 改成 `flags`（`blocks = flags >> 8`）：

    bit0 = 新布局标记   bit1 = 有领地头   bit2 = 值头是 33 桶分布

老文件照常读取：低 8 位为 0 就是"无额外头"；`blocks` 恰好是奇数时会撞上 bit0，
所以加载时再用 `n_params` 交叉核对一次，对不上就退回"整个字段 = blocks"的旧解释
（测试里专门覆盖了 `blocks=3` 的老文件与内置权重 `net_load_mem`）。

### 命令行

    ./build/GoAI train --size 9 --channels 32 --forever \
      --own-weight 0.15 --vdist 1 --resume runs9_s800/best.bin --out runs_step5

热启动：`--resume` 一个老网络时，形状相同的权重原样迁移（卷积层、策略头、
价值头第一层），新头/新块随机初始化 —— 日志会打印 `结构 32ch -> 32ch own vdist33`。
CSV 多了一列 `own_loss`（平均 BCE），曲线图会自动多画一格。

### 测试与校验

测试从 **106 项增加到 226 项**，新增的关键校验：

- 领地头有限差分：全部 `C+1` 个参数，最大偏差 **2.3e-05**（0 超差）
- 值分布头有限差分：最大偏差 **2.5e-05**（0 超差）
- `flags` 往返存取；`GOAI` / `GOAJ(blocks=2)` / `GOAJ(blocks=3)` 老文件加载；
  `net_load_mem`（内置权重）加载；标量值头 → 分布值头的 `net_copy_shared` 迁移
- 终局归属：已知棋形手算核对（一子独占全盘 / 两色共存中立的空区 / 两道墙夹出的地）
  + 不变量 `sum(own) == board_score(komi=0)`
- 干路卷积权重的有限差分只做相关性校验：随机初始化的网络里有大量 ReLU 折点，
  中心差分在这些点上本来就不准（h 从 1e-2 减到 1e-3 时超差数 51 → 3，是折点而非数学错误）

> **顺带修掉一个老 bug**：加残差块之后，三个头部的 1x1 卷积反向用的是 `h2`
> （conv2 的输出），而前向用的是最后一块的输出 `hB` —— 有残差块时这些权重
> （`pw`/`vw`/新的 `ow`）的梯度全是错的，有限差分显示价值头 1x1 偏差达 0.15。
> 现在反向和前向用同一个缓存 `h_head`，偏差降到 1.8e-04（已有 blocks=2 的回归测试）。

### 实测一：冒烟训练（2 轮，热启动 runs9_s800/best.bin，**未标定**）

| 轮 | 策略损失 | 价值损失(CE) | 领地 BCE | 对随机 | 每局手数 | 锚点(成对开局 40 局) |
|---|---|---|---|---|---|---|
| 1 | 2.91 | 2.79 | 0.6675 | 100% | 96.9 | **2.5%** |
| 2 | 3.04 | 1.05 | 0.6571 | 100% | 101.4 | **5.0%** |

结论：**损失全部有限、对随机胜率不掉、每局手数正常（~100 手）** ✓，
但**锚点胜率从 67.5% 崩到 2.5%** ✗ —— 原因是热启动时分布头的 K 个 logits 随机初始化
≈ 均匀分布，搜索值恒为 0，等于把价值头摘掉了（价值 CE 从 `log 33 = 3.50` 开始、
两轮降到 1.05，说明头在学，但搜索已经变瞎）。

### 实测二：标量值头 → 分布值头 的**标定热启动**

把老头的标量读出翻译成一个分布，而不是丢掉重学：

    logit_k = A * center_k * vo_old - GAMMA * center_k^2      (A = 3.0, GAMMA = 0.02)

它仍然是 `ha` 的线性函数，所以可以直接写进新头：
`W2[j][k] = A*center_k*W[j]`、`b2[k] = A*center_k*b - GAMMA*center_k^2`。
数值标定后 `期望值 ≈ tanh(vo_old)`（单测里随机网络最大偏差 0.0072）。

从同一基线（`versions/goai9x9_v5_800sims.bin`，即 step ④ 的 s800 权重）
迁移出来、**不做任何训练**，用成对开局对基线评估（200 模拟）：

| 迁移方式 | 对基线胜率 | 局数 |
|---|---|---|
| 纯拷贝（不加新头，等价于基线自己） | 50.0%（10-10） | 20 |
| 分布头随机初始化（未标定） | 2.5% ~ 5.0% | 40 |
| 分布头标定迁移（`versions/step5_hotstart_9x9.bin`） | 42.5%（20 局）/ **45.0%**（24-30-6，60 局） | 20+60 |

热启动后的价值读出：同一局面老网络 +0.789、迁移后 +0.720（策略完全不变）✓
**标定把"热启动即崩"变成"起点略低于基线（45%）"，实验才有意义** ✓

### 实测三：成对开局锚点验证（runs_step5，5 轮 / 1000 局）

配置：从 `versions/step5_hotstart_9x9.bin` 热启动，`--own-weight 0.15 --vdist 1`，
200 局/轮、800 模拟/手、lr 2e-4；**锚点每轮 40 局成对开局**（对 s800 基线，同一批开局）。

| 轮 | 策略损失 | 价值 CE | 领地 BCE | 对随机 | 锚点(对 s800) |
|---|---|---|---|---|---|
| 1 | 2.598 | 2.515 | 0.6735 | 100% | 45.0% |
| 2 | 2.610 | 1.994 | 0.6438 | 100% | 47.5% |
| 3 | 2.625 | 1.654 | 0.6250 | 100% | 40.0% |
| 4 | 2.641 | 1.346 | 0.6102 | 100% | 35.0% |
| 5 | 2.683 | 1.168 | 0.5973 | 100% | 40.0%（对起点晋级赛 40.0%） |

三个成对开局对拉（200 模拟，固定开局集）：

| 对局 | 胜率 | 局数 | 95% CI |
|---|---|---|---|
| 训练后 vs **基线 s800** | **48.8%**（56-59-5） | 120 | ±8.9 |
| 训练后 vs **起点**（标定热启动） | 37.5%（22-37-1） | 60 | ±12.3 |
| 起点 vs 基线（复核） | 45.0%（24-30-6） | 60 | ±12.6 |

> 对拉是**确定性**的：`eval` 用固定开局集（`--open-plies 4`、固定 open_seed）、
> 温度 0、无 Dirichlet 噪声，所以同一对局跑两次结果**完全一致**
> （起点 vs 基线测了两次，都是 24-30-6）—— 机器负载不影响结果，
> 但要小心：三个对拉的数（48.8 / 45.0 / 37.5）互相略有出入，
> 这是固定开局集上的"非传递性"，不是测量噪声。

**结论（诚实版）**：

- 两个辅助目标**都确实在学**：价值 CE 2.52 → 1.17、领地 BCE 0.673 → 0.597，
  损失全程有限，对随机始终 100%、每局约 97 手 ✓
- 但**棋力没有提升**：锚点 45→47.5→40→35→40（无上升趋势），
  训练后对基线 48.8% ± 8.9% —— 在"从已收敛的 s800 继续微调"这个口径下，
  第 ⑤ 步**没能突破 50%** ✗
- 三个对拉的数互相之间略有出入（48.8 / 45.0 / 37.5），都在 ±9~12 的置信区间边缘，
  说明**差异本身就在噪声量级**；能确定的只有"没有明显变强，也没有崩溃"
- 这与项目已有的规律一致：**已收敛网络继续训练会退化**（README 前面三次复现），
  额外目标改变了损失数字，但没改变这个现象 —— 因为退化来自"在窄数据上过拟合"，
  而不是缺少监督信号
- **下一步建议**：不要在 s800 上继续微调来验证第 ⑤ 步，改成
  ① 从更早的检查点（如 `versions/goai9x9_v4_lr001.bin`）或从零开始，
  让辅助目标参与表示学习；② 扫 `--own-weight 0.3`（领地损失是 81 点平均，
  有效梯度比策略/价值头小得多，0.15 可能偏弱）；③ A/B 两臂必须独占机器。

## 权重文件格式

C 端与 Python 端互通的自定义格式，便于跨平台交换：

    GOAI: uint32 magic('GOAI') | int32 size, planes, channels, vhidden, n_params | float32 参数...
    GOAJ: uint32 magic('GOAJ') | int32 size, planes, channels, vhidden, flags, n_params | float32 参数...

小端 float32，**macOS / Windows / Linux 通用**。把别人练好的 `.bin` 拷过来就能用：
`./build/GoBoard --weights 别人的.bin`

`GOAJ` 的 `flags` 低 8 位是结构标志、高位是残差块数（`blocks = flags >> 8`）：

    bit0 = 新布局标记（blocks 字段有效）   bit1 = 有领地辅助头   bit2 = 值头是 33 桶分布

老文件（`GOAI`、以及 `blocks` 直接写在那个字段里的 `GOAJ`）都能照常读取 —— 详见下面
「第 ⑤ 步」一节。

## 常见问题

**Q：训练要多久才能赢我？**
9 路、8 线程，约 1 小时（3000 局左右）就能稳定赢随机走子；要有点棋形概念大概需要几万局。

**Q：为什么不用 PyTorch 训练？**
C 版不依赖任何框架，任何机器 clone 下来就能跑。PyTorch 版（`gpu/`）是给有显卡的人加速用的，两者权重互通。

**Q：能下 19 路吗？**
可以（`--size 19`），但仓库里的权重都是 9 路的。19 路需要自己训练（更慢，建议有 GPU）。

**Q：AI 什么水平？**
诚实地说：**初学者水平**。它能吃子、做眼、应手，但没有定式体系。作为一个"从零实现 + 能自我进化"的工程样本，它的价值在代码和训练流程本身。

## 自动同步到 GitHub

改代码后自动推送（macOS）：

   双击 启动自动同步.command        # 开一个终端窗口守着，每 60 秒检查一次，有改动就推送
   （关掉窗口或 Ctrl+C 停止）

手动同步：双击 sync-to-github.command，或运行 bash tools/sync_github.sh

> **为什么不用 macOS 后台任务（launchd）？**
> macOS 的安全机制（TCC）不允许后台任务读取「文档 / 桌面 / 下载」目录下的文件，
> 放在这些目录里的项目用 launchd 会报 Operation not permitted。
> 终端窗口有权限，所以自动同步做成终端守护进程。若把项目放在 `~/GoAI` 这类非受保护目录，
> 也可以用 `bash tools/autosync.sh install --force` 装成开机后台任务。
>
> Windows / Linux：把 `tools/sync_github.sh` 加进任务计划程序或 cron 即可，逻辑一样。

## 原来的自动同步到 GitHub

本仓库自带"改了代码就自动推送"的机制（macOS）：

    bash tools/autosync.sh install     # 安装后台任务（只需一次）
    bash tools/autosync.sh status      # 查看状态和最近日志
    bash tools/autosync.sh uninstall   # 卸载

安装后：`src/ include/ gpu/ tools/ standalone/ versions/` 任何文件一改动就会自动提交并推送，
另外每 10 分钟兜底检查一次。同步日志在 `tools/autosync.log`。

不想用后台任务也可以手动同步：双击 `sync-to-github.command`（macOS）或运行 `bash tools/sync_github.sh`。

> Windows / Linux 用户：把 `tools/sync_github.sh` 挂到任务计划程序 / cron 里即可，逻辑完全一样。

## English

A from-scratch Go (Weiqi) AI in pure C11: board rules, PUCT MCTS, and a convolutional
policy/value network with hand-written forward/backward passes — no ML framework required.

- **Play now**: `standalone/PLAY_NOW.bat` (Windows, prebuilt exe, AI weights compiled in) or `make goboard`
- **Train yourself**: `./build/GoAI train --size 9 --channels 32 --forever --threads 8 --out runs_live`
- **With an NVIDIA GPU**: `python gpu/server.py --device cuda` + `./build/GoAI gtrain --remote 127.0.0.1:8899`
- **Measured**: 35,320 self-play games in 8.6 h on an 8-core laptop → 100% vs random, 98.8% vs the previous generation
- **Tests**: `make test` (226 checks). License: MIT.

Weights use a simple little-endian float32 `.bin` format shared between the C and Python sides.
